Azure SQL Database (optional)

The Streamlit app can read the same table from your own Azure SQL Database. Credentials come from .streamlit/secrets.toml or environment variables. They are never typed into a page, shown on screen, or committed to GitHub.

Configuration status: not connected. This web version has no database connection and never asks for credentials. Use the SQL Lab to practise queries, then run them in the Streamlit app with your own secrets.

How the app connects

  1. Create an Azure SQL Database with SQL authentication, and add your IP to the server firewall.
  2. Run sql/setup_sales_table.sql in the portal's Query editor to create dbo.Sales with 240 rows.
  3. Optionally create a read-only user (db_datareader).
  4. Copy .streamlit/secrets.toml.example to secrets.toml and fill in your own values. It is git-ignored.
  5. pip install -r requirements-azure.txt, run the app, choose Azure SQL (optional).

Secrets file (placeholders only)

[azure_sql]
server   = "your-server-name.database.windows.net"
database = "your-database-name"
username = "your-sql-username"
password = "your-password-here"

Never commit secrets.toml. If a password is ever shared by accident, reset it in Azure straight away.

Analytical workloadsTotals, averages, trends over time and group comparisons, the same ideas behind Power BI reports.
Cloud data services (PaaS)Azure SQL Database is managed: Microsoft runs the servers, patching and backups.
SecuritySecrets stay out of code, the server firewall limits who connects, and a read-only user is recommended.
